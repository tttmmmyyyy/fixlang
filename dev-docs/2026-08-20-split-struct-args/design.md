# 構造体の引数をフィールドごとの引数に割る

## 直すもの

`Iterator` の組み合わせ子は、渡された関数を自分の構造体のフィールドに置く。

```fix
type MapIterator i a b = unbox struct { iter : i, f : a -> b };
map = |f, iter| MapIterator { iter : iter, f : f };
```

`closure_specialization` が関数の値を追う道は「引数として渡された関数」と「持ち上げられたラムダの
キャプチャリストのフィールドに入った関数」の 2 つで、構造体のフィールドはどちらでもない。だから
`f` はクロージャの値のまま残り、要素ごとに間接呼び出しになる (#450)。

## 採る形

**構造体の引数を、フィールドごとの引数に割る。** そうすると `f` は**ただの引数**になり、
`closure_specialization` の既存の入り口がそのまま効く。あのパスには 1 行も足さない。

グローバル関数 `f` の第 i 引数が非ボックス構造体 `T { g0 : A0, .., gn : An }` のとき、2 つに割る。

```
f#split : .. -> A0 -> .. -> An -> ..;
f#split = |p0, .., x0, .., xn, ..| (
    let pi = T { g0 : x0, .., gn : xn };
    <f の元の本体>
);

f = |p0, .., pi, ..| (
    let T { g0 : x0, .., gn : xn } = pi;
    f#split(p0, .., x0, .., xn, ..)
);
```

`f` は型も意味も変わらないので、**呼び出し側は 1 か所も書き換えない**。後で `inline` が小さい `f` を
呼び出し側へ入れ、`let_elimination` と RC IR の簡約が構造体の組み立てと分解の往復を畳む。残るのは
フィールドを直に渡す呼び出しである。

## なぜこの形か

**正しさが構成で決まる。** `f` は元の signature と元の意味を持ち、`f#split` は元の本体の前に構造体を
その部品から組み立てるだけである。どちらも「この本体に在るこの型の値はすべて〜」という全称の主張を
必要としない。

#450 に対してもう 1 つの形 (構造体のフィールドを `closure_specialization` の入り口にする、PR #467) を
実装したが、そちらは全称の主張に乗っていて、その主張を守る列挙から**誤コンパイルが 5 件出た**。
列挙の完全性を確かめるものが無く、漏れは静かな誤コンパイルになる。この形にはその主張が無い。

**組み合わせ子の重ね (#452) も同時に解ける。** 割るのを繰り返せば
`FilterIterator { MapIterator { ArrayIterator { arr, idx }, f }, pred }` は
`(arr, idx, f, pred)` になり、内側の `f` も外側の `pred` も引数になる。フィールドの道を 1 段から
n 段へ広げる必要が無い。

## パス列のどこに置くか

`unwrap_newtype` の後、`defunctionalize_fix` と `inline` の前。

- `unwrap_newtype` の後にするのは、フィールド 1 つの構造体はそちらが先に消すからである。
- `inline` の前にするのは、`f` が呼び出し側へ入って往復が畳まれる必要があるからである。

## 割る条件

正しさには要らない。引数が無闇に増えるのを抑えるためだけの条件である。

- 第 i 引数の型が、プログラムが宣言した**非ボックス**の構造体で、穴の開いたフィールドを持たない。
- フィールドが 1 つ以上ある。
- 本体がその引数を分解している (`Pattern::Struct` で分けている)。分解しないなら、割っても中身は
  使われない。
- 割った後の引数の総数が上限を超えない。

上限の値はコーパスを測って決める。

## 段階

1. パスを書き、`arr.to_iter.map(f).fold(0, op)` が 1 要素 0.84 命令に届くかを測る。届かなければ、
   往復が畳まれていないということなので、そこを先に見る。
2. 繰り返し適用して、`map` の重ねと `filter` を挟む形を測る。
3. コーパス 51 ケースの `.text` と命令数を測り、上限を決める。
4. 全テストスイート。

## 測り方

コンパイラは worktree の `target/release/fix`。1 周の費用は
`(I(11) - I(1)) / 10` を `perf stat -e instructions:u` で取る。実装ごとに別のバイナリで測る。
比較の相手は `~/.cache/fixlang-iter-spec/bench-itertest/` の
`a_map_only` / `a_filter_only` / `a_map_filter_fold` / `a_map_filter_toarray2`。
