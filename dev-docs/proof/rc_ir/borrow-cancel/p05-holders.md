## 1. 記法

プログラム `P` の 1 つの実行 `X` を固定する。`X` は段の列 `s_1, s_2, ...` である (D24)。

### 1.1 持ち手と持ち手の単位

**持ち手**とは D25 の 3 種 (生きている活性化・生きているオブジェクト・環境) をいう。

オブジェクトが持つ参照を数える単位を**持ち手の単位**と呼ぶ。オブジェクト `o'` の持ち手の単位は、
`o'` が `#ArrayStorage` のオブジェクトであれば `0` から `size - 1` の各要素の位置と、その要素の型の
`boxed_leaf_paths` が列挙する leaf との対であり、そうでなければ `o'` が保持する値の boxed leaf (D4)
である。この 2 つの形を分けるのは A5 である -- `boxed_leaf_paths` は `#ArrayStorage` に leaf を 1 つ
しか返さないので、この 1 つのオブジェクトについては持ち手の単位は leaf ではなく要素の位置であり、
`0` から `size - 1` の各位置が leaf を 1 組ずつ持つ。

持ち手の単位のうち、inhabited (D16) であって null ポインタでなく、計数下 (D26) のオブジェクトを指す
ものが、参照をちょうど 1 つ持つ (A5)。

### 1.2 素動作

`X` の中でヒープの状態を動かす動作を、次の 6 種に分ける。これを**素動作**と呼ぶ。

- **(α) 受け渡し**: 1 つの参照が 1 つの持ち手を離れ、別の 1 つの持ち手に入る。`H` は変わらない。
- **(β) 生成**: `Cnt` の元 `O` への参照が 1 つ新しく作られ、1 つの持ち手に入る。`H(O)` が 1 上がる。
- **(γ) 割り当て**: 新しいオブジェクト `O` が `Obj` と `Cnt` に入る。`O` への参照が 1 つできて
  `H(O) = 1` となり、1 つの持ち手に入る。さらに、`O` の持ち手の単位のうち inhabited (D16) で非 null
  で計数下 (D26) を指すものの各々が持つ参照は、(i) その直前まで別の持ち手が持っていて、この動作で
  その持ち手を離れたものか、(ii) この動作が新しく作ったもの (指す先の `H` が 1 上がる) の
  どちらかである。
- **(δ) 処分**: 1 つの持ち手が持つ `O` への参照が 1 つ無くなる。`H(O)` が 1 下がる。
- **(ε) 解放**: `H(o) = 0` である計数下のオブジェクト `o` について、`o` が持つ参照 (D25 の 2 番目の
  持ち手) をすべて処分し (指す先の `H` をそれぞれ 1 下げ)、`o` を `Obj` から取り除く。`o` は `Cnt` に
  留まる。
- **(ζ) グローバル化**: 計数下のオブジェクト `O` が `Cnt` を出て、グローバル状態になる (D26)。`O` は
  `Obj` に留まる。

**(γ) が割り当てと書き込みを 1 つの動作にまとめているのは、割り当てた直後の欄が埋まっていないから
である。** `create_obj` は記憶域を取るだけで、欄を埋めるのは呼び出し側である
(`CODE src/object.rs: create_obj` -- 「A fresh object of type `ty`, with its control block
initialized and its remaining fields left undefined for the caller to fill in」)。埋まっていない欄に
ついて `B` が数える対は定まらないので、この文書はそこに点を置かない。

**(ε) が処分と除去を 1 つの動作にまとめているのは、走査が子を release するだけで欄を書き換えないから
である。**処分の途中の欄はその子を指したままなので、そこにも点を置かない。

### 1.3 段の中の素動作の順序

**段の中の素動作の順序は、その段の生成コードがその動作を行う順に取る。**順序は勘定に効く -- (δ) が
`H` を 0 にした時点で (F) の解放が起きるので (D24)、同じオブジェクトについての (β) と (δ) を入れ替え
ると、その段の出口に在るオブジェクトの集合が変わる。

**例外は (ε) の内側の 2 つの動作の並びだけである。**この文書は、(ε) の処分で `H` が 0 になった
オブジェクトの解放を、その (ε) の**後**に置く。コード生成は子の解放を親の記憶域を返す前に行うが
(`CODE src/generator.rs: Generator::build_release_boxed_with` -- `destruction_bb` が `traverse_refs` を
走らせてから `build_free_boxed` を呼ぶ)、その 2 つの間に点を置かなければ、どちらの順に並べても段の
入口と出口の状態は同じである。

**活性化が `Liv` に入る位置と出る位置も、この順序の中に取る。**活性化は、自分の初期 `Obl`
(D10 の初期値) を作る (α) の列の**直前**に `Liv` に入り、終端の `Ret` の消費を行う (α) の列の
**直後**に `Liv` を出る。この位置は (α) の定義が決める -- (α) は 1 つの参照が 1 つの持ち手を離れて
別の 1 つの持ち手に入る動作なので、その参照が入る側の活性化はその時点で持ち手、すなわち生きて
いる活性化 (D25) でなければならない。どちらかの列が空のときは、それぞれ、その段が活性化を作る位置と、
終端の `Ret` の消費を行う位置を取る。`Liv` への出入りは素動作ではないので点を作らない。

### 1.4 点と量

- **点** -- `X` の素動作を時間の順に一列に並べたときの、各素動作の切れ目 (最初の素動作の前と、各素動作の
  後) をいう。**各点の前にある素動作は有限個である** -- 段は列をなし (D24)、1 つの段が無限個の素動作を
  行うならその段は終わらず、終わらない段の後に点は無い。
- **段が終わる** -- その段が行う動作をすべて終えることをいう。節点の実行が終わることも同じ意味で
  いう。終わらない段の後に点は無い。D31 が「ある段が終わらない」を発散の一形態として挙げる。
- **時点** -- `t_0` を `s_1` の前、`t_i` を `s_i` の後 (`i ≥ 1`) の点とする。段は不可分なので、段の内部に
  時点は無い (D24)。(F) の解放と、(F) が作る活性化の内側にも時点は無い (D24)。時点は点である。
- **`Liv(p)`** -- 点 `p` に生きている活性化 (D23) の集合。
- **`Obj(p)`** -- 点 `p` に在るオブジェクトの集合。最初の点 `p_0` (`= t_0`) での値は、環境が実行の
  最初の時点に持ち込んだオブジェクトの全体である (A17 (i-c))。以後は (γ) が入れ、(ε) が取り除く。
  この集合が各点で D25 の「生きているオブジェクト」に一致することは `<1>0a` が示す。
- **`Cnt(p)`** -- 点 `p` に計数下 (D26) であるオブジェクトの集合。(γ) が入れ、(ζ) が取り除く。
- 計数下オブジェクト `O` について:
  - `H_p(O)` -- `O` の参照カウント (D7)。
  - `A_p(O) := Σ_{a ∈ Liv(p)} (Obl(a) が持つ O への参照の個数)`。
  - `B_p(O) :=` 対 `(o', u)` の個数。ここで `o' ∈ Obj(p)`、`u` は `o'` の持ち手の単位 (第 1.1 節) で
    あって、`p` において inhabited (D16) であり、null ポインタでなく、それが指すオブジェクトが `O`
    であるものである。
  - `C_p(O) :=` `E` が持つ `O` への参照の個数 (D22)。
- **`INV(p)`** -- すべての `O ∈ Cnt(p)` について `H_p(O) = A_p(O) + B_p(O) + C_p(O)`。

`A`、`B`、`C` は D25 の 3 種の持ち手に 1 対 1 に対応する。`B` が対を数えるのは A5 による -- 生きている
オブジェクトの持ち手の単位のうち、inhabited で非 null で計数下を指すものが、参照をちょうど 1 つ持つ。

**`Obl(a)` が参照の多重集合として定まるのは、`a` の除去がすべて合法である間である。** この文書の帰納は
点を 1 つ進めるごとに、その点までの許容性 (下記) から D11 を当てて除去の合法性を確かめるので、帰納が
届いた点までの `Obl` は定まっている。`A_p` はその上で数える。

### 1.5 別名類の帳簿と許容性

別名類 (D33) と `held` (D34) の量を、実行の点の上で読む。

- 計数下の別名類 `C` と点 `p` について:
  - **`held_p(C)`** -- D34 の表が定める量。D34 の表の各事象は第 1.2 節の素動作の 1 つの中で起きるので、
    その素動作の直後の点で `held` が動くものとして各点へ延ばす。1 つの素動作が複数の事象を運ぶことが
    ある -- (γ) は割り当てと、その (i) が挙げる各参照の移動を 1 つの動作にまとめる -- ので、その点では
    運ばれた事象の増減をすべて足す。`Obl` の側も同じ素動作の中で同じ事象を受けるので、2 つの量は同じ
    点で動く。開始の 3 行が置く値は、D34 のとおり、その類の `ρ` 終端の変数が値を得る点に置く。
    時点についてこの延長は D34 の値と一致する -- 段の境界の間の増減は同じ事象の集まりだからである。
  - **`β(C)`** -- `C` の `ρ` 終端が借用する (D14) パラメータ・capture の leaf であるとき 1、そう
    でないとき 0。
  - **`d_p(C) := held_p(C) - β(C)`** (A19 (i) の `d`)。
- **`S_{a,p}(O)`** -- 活性化 `a` の計数下の別名類のうち、`obj(C) = O` であり、開始の点が `p` 以前で
  あるものの全体 (A19 (i) の `S`)。
- **`ADM(p)`** -- `p` に生きている各活性化 `a` と各 `O ∈ Cnt(p)` について
  `H_p(O) ≥ Σ_{C ∈ S_{a,p}(O)} d_p(C) + [S_{a,p}(O) に β(C) = 1 である類が在るならば 1]`。
  これが A19 (i) の不等式であり、D21 が活性化に課す制限である。
- **`p` まで許容的** -- `p` 以前 (`p` を含む) のすべての点で `ADM` が成り立つこと。

**`H` は実行の量である。** D7 が定める参照カウントはヒープの量であり、`H_p(O)` はそれである。D21 は
1 つの本体を見るとき `H` を活性化の側の与件として扱うが、実行を見るこの文書ではヒープの側の量として
読む。実行が作る各活性化について、その与件の側の `H` を実行の `H` に取ると D21 の制限が満たされる、
というのが P28 (b) である。

**D11 が課す条件は、その点までの接頭について読む。**(S-a) は「取り除かれる参照はその時点の `Obl` に
入っている」であり、取り除かれる参照の集合はその節点と入口の値で決まり、`Obl` はそこまでの接頭で決まる。
(S-b) は終端の `Ret` の消費を行った後の `Obl` についてであり、同じである。この読みを使うのが
`<1>4c` である。

### 4.2 オペランドを適用する `Llvm` の段が、オペランドでない値を渡すときの `Obl(a)` の動き

D24 の (E2) の行き先の表は、`Llvm` の節点について `Obl(a)` を離れる参照を「D9 の `Llvm` の行」とする。

呼び出し先として渡す -- 1 回目の適用が返した関数がそれであり、`applies_a_function_operand` を宣言する
8 種の op のうち 5 種がこの形を取る (`InlineLLVMFixBody`、

**要る形**: 同じ段落の「`Obl(a)` の動きは D9 の `Llvm` の行と A3 の宣言が決めるので、この表の行は
そのままである」を、オペランドの側についての文だと限ること。この文を網羅の主張として読むと、
オペランドでない値の参照は `Obl(a)` を離れないことになり、その参照を渡された先の活性化の `Obl` と
