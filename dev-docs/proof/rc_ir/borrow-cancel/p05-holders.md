## 1. 記法

プログラム `P` の 1 つの実行 `X` を固定する。`X` は段の列 `s_1, s_2, ...` である (D24)。

### 1.1 素動作

`X` の中でヒープの状態を動かす動作を、次の 6 種に分ける。これを**素動作**と呼ぶ。持ち手とは D25 の
3 種 (生きている活性化・生きているオブジェクト・環境) をいう。

- **(α) 受け渡し**: 1 つの参照が 1 つの持ち手を離れ、別の 1 つの持ち手に入る。`H` は変わらない。
- **(β) 生成**: `Cnt` の元 `O` への参照が 1 つ新しく作られ、1 つの持ち手に入る。`H(O)` が 1 上がる。
- **(γ) 割り当て**: 新しいオブジェクト `O` が `Obj` と `Cnt` に入る。`O` への参照が 1 つできて
  `H(O) = 1` となり、1 つの持ち手に入る。さらに、`O` が保持する値の boxed leaf (D4) のうち inhabited
  (D16) で非 null で計数下 (D26) を指すものの各々が持つ参照は、(i) その直前まで別の持ち手が持っていて、
  この動作でその持ち手を離れたものか、(ii) この動作が新しく作ったもの (指す先の `H` が 1 上がる) の
  どちらかである。
- **(δ) 処分**: 1 つの持ち手が持つ `O` への参照が 1 つ無くなる。`H(O)` が 1 下がる。
- **(ε) 解放**: `H(o) = 0` である計数下のオブジェクト `o` について、`o` が持つ参照 (D25 の 2 番目の
  持ち手) をすべて処分し (指す先の `H` をそれぞれ 1 下げ)、`o` を `Obj` から取り除く。`o` は `Cnt` に
  留まる。
- **(ζ) グローバル化**: 計数下のオブジェクト `O` が `Cnt` を出て、グローバル状態になる (D26)。`O` は
  `Obj` に留まる。

**(γ) が割り当てと書き込みを 1 つの動作にまとめているのは、割り当てた直後の欄が埋まっていないから
である。** `create_obj` は記憶域を取るだけで、欄を埋めるのは呼び出し側である
(`CODE src/object.rs: create_obj` -- 「A fresh object of type `ty`, with its control block
initialized and its remaining fields left undefined for the caller to fill in」)。埋まっていない欄に
ついて `B` が数える対は定まらないので、この文書はそこに点を置かない。

**(ε) が処分と除去を 1 つの動作にまとめているのは、走査が子を release するだけで欄を書き換えないから
である。**処分の途中の欄はその子を指したままなので、そこにも点を置かない。

### 1.2 段の中の素動作の順序

**段の中の素動作の順序は、この文書が選んでよい。** 段の中に D24 の時点は無いので、`INV` (下記) を
時点へ運ぶのに要るのは段の入口と出口の状態だけである。この文書は、(ε) の処分で `H` が 0 になった
オブジェクトの解放を、その (ε) の**後**に置く。コード生成は子の解放を親の記憶域を返す前に行うが
(`CODE src/generator.rs: Generator::build_release_boxed_with` -- `destruction_bb` が `traverse_refs` を
走らせてから `build_free_boxed` を呼ぶ)、その 2 つの間に時点は無いので、どちらの順に並べても段の
入口と出口の状態は同じである。

### 1.3 点と量

- **点** -- `X` の素動作を時間の順に一列に並べたときの、各素動作の切れ目 (最初の素動作の前と、各素動作の
  後) をいう。
- **時点** -- `t_0` を `s_1` の前、`t_i` を `s_i` の後 (`i ≥ 1`) の点とする。段は不可分なので、段の内部に
  時点は無い (D24)。(F) の解放と、(F) が作る活性化の内側にも時点は無い (D24)。時点は点である。
- **`Liv(p)`** -- 点 `p` に生きている活性化 (D23) の集合。
- **`Obj(p)`** -- 点 `p` に在るオブジェクトの集合。(γ) が入れ、(ε) が取り除く。時点では D25 の「生きて
  いるオブジェクト」(割り当てた段より後、解放する段より前) に一致する。
- **`Cnt(p)`** -- 点 `p` に計数下 (D26) であるオブジェクトの集合。(γ) が入れ、(ζ) が取り除く。
- 計数下オブジェクト `O` について:
  - `H_p(O)` -- `O` の参照カウント (D7)。
  - `A_p(O) := Σ_{a ∈ Liv(p)} (Obl(a) が持つ O への参照の個数)`。
  - `B_p(O) :=` 対 `(o', λ)` の個数。ここで `o' ∈ Obj(p)`、`λ` は `o'` が保持する値の boxed leaf (D4)
    であって、`p` において inhabited (D16) であり、null ポインタでなく、`obj(o', λ) = O` である。
  - `C_p(O) :=` `E` が持つ `O` への参照の個数 (D22)。
- **`INV(p)`** -- すべての `O ∈ Cnt(p)` について `H_p(O) = A_p(O) + B_p(O) + C_p(O)`。

`A`、`B`、`C` は D25 の 3 種の持ち手に 1 対 1 に対応する。`B` が対を数えるのは A5 による -- 生きている
オブジェクトの inhabited で非 null で計数下を指す leaf が、参照をちょうど 1 つ持つ。

## 4. README について

### 4.1 (A-init) -- 実行の最初の時点の状態が定まっていない

D24 の「実行の最初の時点」の段落は 2 つのことを書く。第 1 文は

> **実行の最初の時点には参照が 1 つも無い。** 参照を作るのは D10 の生成の表、(F) の retain、そして
> `InlineLLVMBoxedFromRetainedPtrIOS` が環境から受け取る行の 3 か所だけであり、どれも段の中で起きる。

であり、最後の文は

> `FFI_EXPORT` のエントリ点が boxed な引数を取るとき、その参照は環境が持ってきたものであり、
> A17 (i) がそれを渡すことを言う。

である。**後者は前者の場合分けの外にある。**環境が持ってきた参照は、`X` のどの段も作っていないので、
第 1 文が数え上げる 3 か所のどれでもない。

この場合が実在することはコードが決めている。boxed な値はエントリ点の署名では不透明なポインタとして
渡り (`CODE src/ffi.rs: c_boundary_tycon`)、エントリ点は C の引数の 1 語から Fix の値を組み立てる
(`CODE src/ast/export_statement.rs: ExportStatement::implement`)。その値のオブジェクトへの参照は、
C の呼び出し元が持っているものであり、A17 (i) がそれを渡すことを言う。

**要る形**: 第 0 節の (A-init)。すなわち「`t_0` において各計数下オブジェクト `O` について
`H_{t_0}(O) = B_{t_0}(O) + C_{t_0}(O)`」である。果たす者は環境であり、A17 の 4 つ目の節として置くのが
形に合う。A17 (i) が「環境が活性化を作るとき、D10 の初期値が要求する参照を渡し」と書くのは、環境が
その参照を持っていることを前提にしているので、その持ち分が勘定に合っていることを言う節がその隣に
要る。

**C のエントリ点では読まない。**C のエントリ点は `argc` と `argv` をグローバル変数へ格納し、グローバル
`main` を読み、`IOState` を渡す (`CODE src/build/build_object_files.rs: build_main_function`,
`CODE src/fixstd/builtin.rs: run_ios_runner`)。`IOState` は `is_unbox` が真で `fields` が空の primitive
なので boxed leaf を持たない (`CODE src/fixstd/builtin.rs: bulitin_tycons`)。グローバル `main` の読みは
アクセサを通り、初期化されていなければ (E7) の段が走る。よって `t_0` に計数下オブジェクトは無く、
`<1>3` の `<2>3` の側が当たる。

### 4.2 段の不可分性と、活性化を作る (E2) の段

D24 は「段は不可分であり」と書き、(E2) の「オペランドを適用する」の段落は「**1 つの段が活性化を
2 つ以上作りうる**」と「`a` はそれが終わるまで中断中である」と書く。(E3) については、作られた活性化の
段が段の列に並び、その返りが (E4) の段である。同じ読みを (E2) のこの段に当てると、1 つの段が段の列を
跨ぐことになり、不可分性と食い違う。

**この文書が取る読み**: (E2) のこの段が作る活性化の実行は、(F) の解放が作る活性化と同じく、その段の
**中**で終わる。すなわちその内側に D24 の時点は無い。段の中で実行される `App` の節点 -- (F) の解放が
作る活性化の中や、この (E2) の段が作る活性化の中に在るもの -- についても同じ読みを取る。その呼び出し先
の活性化はその段の中で終わり、(E3) と (E4) の記述はその形を与えるだけで、段を 1 つ増やさない。

この読みを取るのは、不可分性が `<1>9` の帰納の土台だからである。`<1>5`、`<1>6`、`<1>7` はどれも
「段であるかどうか」を読まない形に書いてあるので、README がもう一方の読みを取るなら、`<1>8` の
`<2>3` が数える範囲が変わるだけで、素動作への分解はそのまま立つ。

### 4.3 D9 の終端の `Ret` の行が関数本体だけを名指している

D9 の消費の表の最後の行は「関数本体の終端の `Ret(x)`」である。D23 は活性化の本体を「ある関数の `body`
