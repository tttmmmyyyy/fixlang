# 証明の機械検査

`dev-docs/proof` の下の構造化証明について、構文的に決まる規則を全数検査する道具である。
**証明を書く者と検証する者は、これを走らせてから自分の仕事を始める。**
手で書いた走査は 1 本あたり数十万トークンかかり、実装が人ごとに違って結果が揃わない。

| 道具 | 見るもの |
|---|---|
| `proof_links.py` | `CODE` 引用が名指す記号の実在と、ソース側の `// PROOF:` コメント (`--write` で再生成) |
| `proof_steps.py` | 段の数、`BY` のトークンの分類、`DEF`/`EXT` 名札の実在、`<k>n` のスコープ規則、支えの無い段、読点の落ち |
| `proof_index.py` | 項目の依存グラフ。`--frontier` が「動いた項目を引いている項目」を行つきで出す (`--assign` で同一性、`--accept` で読み直した印) |
| `proof_readers.py` | 枠が証明ファイルを読み手として名指す箇所の一覧 (照合の材料) |
| `proof_prose.py` | 引用でない地の文のうち、枠に当てる要のあるものとコードに当てる要のあるものの一覧 |
| `proof_steps.py --cites <名前>` | その名前を `BY` で引く段の一覧 (仮定や定義が動いたときに読み直す段) |

## 走らせ方

```
python3 dev-docs/proof/proof_links.py
python3 dev-docs/proof/proof_index.py <証明のディレクトリ>
python3 dev-docs/proof/proof_quotes.py <証明のディレクトリ>
python3 dev-docs/proof/proof_steps.py <証明のディレクトリ>
python3 dev-docs/proof/proof_prose.py <証明ファイル>
```

## 読むときと書くとき

**証明を読む者は、生のファイルではなく道具の出す版を読む。** `BY` が挙げるのは id なので、
生のファイルからはその段が何に依拠しているか読めない。

```
python3 dev-docs/proof/proof_index.py --render <証明ファイル>          # 引用を題に展開した版
python3 dev-docs/proof/proof_index.py --bundle <証明ファイル>          # そのファイルが引く命題の本文
python3 dev-docs/proof/proof_index.py --bundle <証明ファイル> --item L14   # 1 つの命題ぶん
python3 dev-docs/proof/proof_index.py --show <id>                     # id の中身
```

**書く者は名前で書き、`--convert` に id へ直させる。**

```
BY D25, L11, CODE src/rc_ir/ownership.rs: origin      <- こう書いて
python3 dev-docs/proof/proof_index.py --convert <証明ファイル>
BY <ref id=9d74736/>, <ref id=4eeb2d5/>, CODE ...     <- こうなる
```

**`--convert` が書き替えるのは `BY` の行だけで、その中の引用と `` ` `` で囲んだ部分は除く。**
散文の中の名前を綴りから探すと、参照でないものを参照にする -- 実測で Rust の型変数 `&T` が
主定理 `T` の id に潰れた。**解決しない名前は書き替えずに数えて返す。**

**変換したら、グラフを作り直して同じであることを確かめる。** 実測で、その検査だけが
3 つの破壊を出した -- 別ファイルの命題を引く側の同名の命題に潰したもの、引用の中を書き替えたもの、
行を跨ぐ引用を守れていなかったもの。**どれも読んでも分からない** (id は正しく見える)。

## 参照は id である

- **タグは 1 種類だけである。** 本文を埋め込む `<quote>` は置かない -- 読む版は道具が組み立て、
  **そのファイルが引く命題の本文は束が運ぶ** (`--bundle`)。同じ本文が束と証明の 2 か所に在ると、
  片方だけが古くなる。
- **表示は道具が出す。** `<ref id=e3436e8/>` は「実行 (e3436e8)」と描く -- 題は命題の見出しから
  取るので、題が変われば表示も変わり、**引く側は 1 か所も古くならない。**
- **番号はソースに置かない。** 番号を置くと人がそれを散文へ写し、写された番号は道具の外に出る。

**引く側を id にすると `proof_quotes.py` と `proof_prose.py` の存在理由が消える** --
引用は道具が埋めるので手打ちの引用が無くなり、言い替える理由も無くなる。

## 仮定を走査で果たす -- `SCAN`

**証明のステップが、コードについて閉じた数え上げをしてはならない。** 「クレート全体で 6 か所」
「呼び出し元は 4 つ」は、**仮定の仕事をステップの中でやっている形**である。果たす者が名指されず、
尽きているかを誰も見ない。実測で、3 つのファイルでこれが最大の族だった。

**数え上げは仮定に置き、その仮定を走査が果たす。**

```
**A27 (状態の欄を書くのは 3 つの生成コードだけ)** -- 果たす者: 下の `SCAN`。
…本文…

SCAN src/ `.set_refcnt_state(`
  = src/object.rs: create_obj -- 割り当てたオブジェクトへ `LOCAL`
  = src/generator.rs: build_mark_boxed_with -- 印を付ける箇所
  = src/generator.rs: build_branch_by_is_unique -- threaded の腕
```

`proof_links.py` が走査を実際に走らせ、挙がった一覧と突き合わせる。**要素が増えても減っても出る。**

- **述語は走らせられる字面で書く。** 散文の述語 (「`set_refcnt_state` の呼び出し」) は走らない。
- **走査は字面の上界である。** `RcExpr::Retain(` は構成とパターンの両方に当たる。
  **だから各要素が何であるかを `--` の後に書く** -- 網羅は機械が保証し、分類は書く者がやる。
- **個数は書かない。** 一覧が在れば個数は一覧の長さであり、一覧と独立に古くなる。
  実測で、一覧が正しく数だけが誤っていた箇所がある。

## 命題と、その依存

**命題**とは、証明を持つ主張である。定義 (`D*`) と仮定 (`A*`) は証明を持たない。
**枠に置くか証明ファイルに置くかの違いはあるが、種類の違いは無い** -- `L14` も `P28` も命題である。

- **命題の見出しは、命題の名前を名乗っている行である。** 名前の後に何が続くかは問わない。
  実測で名乗り方が **8 通り**あり、形を数え上げていたために 2 通りを落として、
  **本文の 44% がどの命題にも属さず、`D27` への引用 115 件が宙に浮いていた。**
- **言明が枠に、証明が別のファイルに在る形がある** (`p05` は `P28` の証明である)。
  そのファイルの題が名乗る命題に、局所の命題に属さない引用が帰属する。
- **指紋は言明の指紋である。** 枠の項目は全体が言明で、証明の命題は言明の段落だけである --
  **証明が変わっても、その命題を引く側は影響を受けない。**
- **漏れは構成で見える。** 形で見つける以上は必ず漏れるので、道具は毎回
  **どの命題にも属さない本文の行数と、解決しない引用の件数**を数えて出す。

**`--frontier` は「動いた命題を引いている命題」を、ファイルと行と名前で出す。**
**`--bundle` はその命題が引く命題の本文を組み立てる** -- 読み直す者に渡すのはこれである。

## 道具を直すのは、道具が見落としたものが出たとき

**`proof_steps.py` は別のファイルの命題を引く形を知らなかった。** 枠の第 5 節が認める
`p15 の L11` の形が「未分類」に出ていた (1 ファイルで 15 件、全部正当)。

**`proof_prose.py` は助数詞「つ」を数えていなかった。** 「`origin_inner` の match は 8 つの腕」という
**コードと食い違う数の主張が 1 周見逃された。** 無条件に入れると「2 つのスロット」のような数式の文が
3 倍混じるので、**コードの構造を数える語 (腕・構成子・変位・欄・呼び出し・分岐など) が続くときだけ**
数える形にした。修理前のファイルに当てて、その主張が出ることを確かめてある。

**`proof_quotes.py` は blockquote を見ていなかった。** 証明は仮定の文面を再掲するとき
`> ` の blockquote を使うことがあり、**そこに A19 (ii-c) の量化を落とした引用が 2 本のファイルに
隠れていた。** いまは blockquote も同じ錨の規則で当てる。

**`proof_steps.py` は名札の宣言の形を 1 つ見落としていた。** `` - **`EXT 名前`** `` と名札の語ごと
バッククォートに入れる形を、`EXT 名前` という名前の名札として登録していたので、
**その形で宣言するファイルの引用が全部「名札の不在」に出ていた** (1 ファイルで 14 件、全部空振り)。
**本当に名札を落とした周と区別が付かない状態だった。**

**`proof_steps.py` は `BY <1>5, D11, D14, D23 DEF D12` を通していた。** `D23` の接頭辞で分類が成立し、
その後ろの `DEF D12` が消えていた -- **接頭辞だけで分類すると、後ろに付いたものが見えなくなる。**
いまは事実の後ろに続く `DEF` / `EXT` の名前も名札として検査するので、この形は「名札の不在」に出る。

**`proof_steps.py` は他のファイルの名札を引く側の文書に探していた。** 枠の第 5 節が認める
`p13 の DEF 名前の活性` の形について、`DEF 名前の活性` を**引く側**の宣言と照合していたので、
**その形の引用が全部「名札の不在」に出ていた** (1 ファイルで 13 件)。いまは `p13` で始まる同じ
ディレクトリの文書を引いてそこで照合する。**この形の 13 件のうち 7 件は本当の欠落だった** --
`DEF ρ-歩みと ρ-終端` は枠の D33 へ移っていて `p13` にもう無く、空振りの 6 件に紛れていた。

**`proof_steps.py` は括弧つきの名札の宣言と引用を別の名前にしていた。** 引く側は `(` の前で切って
`EXT derive(Clone)` を `derive` として照合するのに、宣言の側は `derive(Clone)` のまま登録していたので、
**その名札を引く段が全部「名札の不在」に出ていた** (1 ファイルで 11 件、全部空振り)。いまは宣言も
`(` の前で切った形を併せて登録する。引く側の切り方は変えていないので、見分けの細かさは落ちない。

**`proof_steps.py` は言明・`CASE`・背理法が置く仮定を知らなかった。** `仮定` と `帰納法の仮定` は
事実として分類するのに、`本命題の仮定`・`本場合の仮定`・`背理法の仮定` は「未分類」に落ちていた
(4 ファイルで 35 件)。**未分類は仕分けの依頼なので、空振りが多いと本物がそこに埋まる。**

**見落としを見つけたら、そのときのファイルを道具に当てて、直した道具が実際にそれを出すことを
確かめる。** 上の例では、修理前の `p70-main-theorem.md` に当てて `<1>6: DEF D12` が出ることを確かめた。
他のファイルの名札の分は、`p40-cancel-soundness.md` に当てて `DEF ρ-歩みと ρ-終端` の 7 件だけが
残り、`DEF 名前の活性` と `DEF 実行時の作用` の 6 件が消えることを確かめた。

## 道具が見ないもの

**道具が出すのは「当てる要のある箇所の一覧」までである。当てるのは読む者がやる。**
言い替えた地の文とコードを数えた文は `proof_prose.py` が**漏れなく挙げる**が、
枠の本文とコードのどちらに当てるかは文ごとに違うので、判定は機械にできない。

**内容を見る検査は、機械にできない。**

- `BY` が挙げた根拠が結論を**支えているか**。
- 数え上げが**尽きているか** (在りかを述語で書き、その述語で全項目を分類し直す)。
- 引用した箇所が、コードの**意味**として主張どおりか。
- 枠に在るのに**引いていない**節が、その段にとって要るものか
  (`proof_readers.py` は名指しの一覧を出すだけで、判定はしない)。

**道具に残っている限界。**

- **`proof_quotes.py` の帰属は錨 (24 字) で決めるので、同じファイルの中の自己引用が枠の別の文と
  偶然重なると誤検知する** (実測で 3 件)。**引用がどの項目のものかを書式が持っていれば消える種類の
  誤りである。**

**まだ機械化していないもの。**

- **枠が動いたとき、どのファイルを読み直す要があるかの述語。** いまは全ファイルを毎周検証している。
  各ファイルが `BY` で引く枠の項目は `proof_steps.py --cites` で取れるので、
  **その項目が最後の検証より後に動いたか**を見れば、静かなファイルを根拠つきで飛ばせる。
